## ✨ New Features
- **Delete Memory and Coverage Check (fork)** - A message you delete in the archive on purpose (one, many, by filter, API, MCP) or that the local retention policy removes is no longer archived again from the same account: the database writes a marker (identifiers only: no subject, sender or text) in the same transaction as the delete and its audit entry (`email.deleted` now carries `markerId`). The sync skips matching messages before the download (Gmail id, or Message-ID + size + folder) and after it (SHA-256), and fails closed: a check that cannot be made fails the message instead of importing it. The sync result shows "Skipped, deleted by you"; the account page lists the skipped messages with Allow again (audit entry `marker.released`, then a Full resync). Deleting an account forgets its markers. New **Coverage check** on the account page (read-only towards the mailbox): every message on the server goes into exactly one group (archived, deleted by you, quarantined, filtered out, not yet seen) and the sum is checked. New table `DeletedMessageMarkers`, new column `SyncProblemMessages.GmailMessageId`, the `email.deleted` trigger is replaced (additive migrations). See `doc/DeleteMemory.md`.
- **Verify-All Integrity Job (fork)** - Admin API `POST /api/v1/integrity/runs` starts a pass over every email that re-hashes its stored original and compares the database copy with it; `GET /api/v1/integrity/runs` and `/runs/{id}` show counters and findings (Invalid, Missing, NotStored, Inconsistent). `Integrity:VerifyAllIntervalHours` runs it on a schedule (0 = off). `GET /api/v1/emails/{id}/integrity` verifies a single email.
- **Gmail Filter, Labels and Marketing (fork)** - Per Gmail account: a search filter (default `-label:Marketing`, includes sub-labels) added to every folder search so tagged mail is never downloaded (Test button, chained on change, shown on the Integrity & Storage page); sync only the folder with all mail by default; each message's Gmail labels, message id and thread id are stored (metadata, refreshed daily, `Integrity__ChainLabelChanges` to chain changes), the Sent label sets the direction; label chips, a "Tagged Marketing" view, the label filter in the list, the API (`label=`), MCP and the bulk "delete all matches" job.
- **Problem Messages and Cheaper Syncing (fork)** - A message that fails 3 times in a row is set aside (listed on the Integrity & Storage page and `GET /api/v1/integrity/sync-problems`, retried by an administrator) instead of holding back the whole mailbox; messages already archived are recognised by Message-ID and size before their body is downloaded; a different message that reuses a Message-ID is kept as a second email.
- **Integrity Check Hardening (fork)** - Calendar-typed attachment rows are compared; an email archived after the chain began without a chain entry is a finding (`ChainMismatch`, state `Gap`); a changed display time zone is no false alarm; a settings reset goes to the configured value and asks for the password when that lowers a protection; the old signing key beside the manifests is moved; wrong passwords are counted per address and chained; a GET no longer writes audit records.
- **OCR Mode Shows Only Off and On (fork)** - The settings page no longer offers a graphics-card (GPU) option, because no GPU build exists and it behaved like the processor. `Ocr__Mode=gpu` from the environment is still accepted and uses the processor. The reasons are documented under "Development: GPU OCR" in `doc/INTEGRITY-DESIGN.md`.
- **Integrity & Storage Page (fork)** - Admins get a menu entry with verify-all, audit chain check, signed manifests (create, verify, download, public key, the `openssl` command), the Trash for deleted originals (list, restore, empty now), attachment text/OCR status and rescans, and the settings. Locked settings (storage mode, originals location, Required, audit chain, key paths) are shown read-only; editable ones (schedules, Trash time and interval, OCR mode and limits) are one form with one Save, saved all or nothing, stored in the database and applied without a restart (OCR threads after a restart). An environment variable pins a setting. When a pending change lowers a protection, Save opens a dialog that lists the changes and asks for your password (the server enforces it); every change is recorded in the audit chain and the access log before it is applied. Calm theme colours and plain wording. New table `AppSettings` (additive migration).
- **Trash for deleted originals (fork; the option names still say Bin)** - **On by default.** An original (hash-named file, as used by lean mode) that no email refers to any more is moved to a `.bin/` folder, kept for 30 days (`RawMessages__OriginalCleanup__BinRetentionDays`) and then deleted permanently; restorable until then (`POST /api/v1/integrity/original-cleanup/restore`, by SHA-256). Every move, restore and purge is written to the audit chain first; at most 1000 files per run; files written in the last 24 hours are left alone; the first run after an upgrade only moves, never deletes. It does nothing unless originals are hash-named filesystem files. Switch it off with `RawMessages__OriginalCleanup__Enabled=false`. **It only moves an original when the history log holds a delete request for it, no email refers to it, the database and the originals folder carry the same archive identity (marker file `.archive-id`), and the run passes a circuit breaker (more than 5% of the originals, at least 50, needs "Run anyway"); other unreferenced files are only listed.** After the retention period the original FILE is erased for good (subjects in the access log and backups are not touched); extracted attachment text is removed once no attachment has that hash.
- **Review fixes for the integrity features (fork)** - A refused or failed email is now a failed email: the sync does not move past it (it used to count as already archived). `RawMessages:Required` refuses only when no verified original exists (calendar invites and attachments that cannot be found again are stored in full with their original). "Valid" now also checks HTML body, dates, display names and attachment bytes, names, types and sizes, consults the audit chain (new status ChainMismatch; emails stored before the chain are reported Unchained) and reports damaged originals as Invalid. Every email deletion is recorded in the chain by a database trigger, access-log rows are chained whoever writes them, and manifest/chain verification reports removed or changed evidence. The signing key moves to the DataProtection key directory (0600, never silently re-created). The storage migration refuses hash-named/lean originals unless `Storage:AllowHashNamedMigration` and never deletes shared files. Settings: see doc/Setup.md.
- **Lean Storage for EML Import and Graph (fork)** - Under `Storage__Mode=Lean` EML import and Graph sync now archive lean like the IMAP sync: the original is written hash-named and verified first, attachments are found again in it by hash, the rest of the row keeps only index data (stored in full when that cannot be verified, refused under `RawMessages__Required`). **Behaviour change:** an mbox import is refused in lean mode and under `RawMessages__Required` (mbox copies are re-serialized, not original bytes); set `Storage__AllowSerializedImports=true` to allow it, the originals are then labelled `serialized`.
- **OCR for Scans and Photos (fork)** - With `Ocr__Mode=cpu`, images and scanned PDFs are read by a bundled CPU OCR engine (PaddleOCR PP-OCRv5 models through ONNX Runtime, about 13 MB, downloaded and hash-checked when the image is built) and the text becomes searchable. Off by default; limits for image size, time and pages; earlier NeedsOcr results are queued again when the engine is on (or `POST /api/v1/attachment-text/rescan?scope=needsocr`). `Ocr__Mode=off` and images built with `OCR_MODELS=skip` are unaffected.
- **Backup Verification (fork)** - `tools/compare-manifests.py` compares two copies of the Manifests folder (a backup and the live archive) and reports missing, changed and new emails after checking both signatures; `doc/BackupVerification.md` is the runbook for consistent backups and a monthly restore test.
- **Attachment Text for Search (fork)** - A background worker (`Ocr__Mode=cpu` or `gpu`; off by default) reads the text layer of PDF, Word, Excel, PowerPoint, OpenDocument, text, HTML and attached-message files and adds it to the email's search text, so words that exist only inside an attachment are found. An attachment in many emails is read once (keyed by SHA-256). Scans and photos are marked `NeedsOcr` for a later OCR engine. Admin API: `GET /api/v1/attachment-text/status`, `POST /api/v1/attachment-text/rescan`. The migration rebuilds the full-text index on the longer expression and lets the locked-email trigger ignore the two derived columns.
- **Chain Anchor (fork)** - `GET /api/v1/integrity/chain/anchor` returns the chain head as one line (time, seq, hash, public-key fingerprint) and `GET /api/v1/integrity/chain/entries/{seq}` the hash of one entry. `tools/pull-anchor.sh` collects the anchor on another machine, refuses a head that went backwards, and checks that the earlier stored head is still in the archive's chain unchanged, which catches a chain that was rewritten together with its manifest.
- **Hash-Chained Audit Trail (fork)** - New append-only `AuditChain` table (database trigger refuses UPDATE, DELETE and TRUNCATE). Every access-log entry, every stored original (email id and SHA-256, from any import path) and every verify-all run is appended with the hash of the previous entry. Admin API: `GET /api/v1/integrity/chain/head` (sequence and hash to copy off the machine) and `GET /api/v1/integrity/chain/verify` (first break, hash changes since archiving, emails never chained). `Integrity__AuditChainEnabled` (default true).
- **RawMessages:Required (fork)** - With `RawMessages__Required=true` an email whose original cannot be kept (no capture, over the size limit, or lean ingest could not verify it) is not archived: it is logged at error level, counted in the metrics and reported as failed, so the next sync tries it again. Applies to IMAP sync, Graph and EML/mbox import. Needs `RawMessages__Enabled=true`. Default `false` keeps the upstream behaviour.
- **Integrity Panel and MCP Tool (fork)** - The email detail page has an Integrity panel with a Verify now button (`GET /Emails/Integrity/{id}`, same check as the API). MCP gains `get_email_integrity`, and `get_email`, `get_attachment` and `get_email_eml` now read lean-stored emails from the original.
- **Health and Metrics for External Monitoring** - Authenticated endpoints under `/api/v1` expose liveness, readiness, aggregate health and a Prometheus-compatible metrics endpoint. All require an existing API key whose user is an administrator; a non-admin key gets 403. Metrics cover archived emails, accounts, missing originals, sync age and failure counters, and are built by a background snapshot so a scrape never scans the archive. The metrics endpoint is disabled by default with `Metrics:Enabled=false`.
- **Bulk Delete by Filter** - Delete every email matching the current search filter in one background job. The confirmation requires the exact match count, locked emails are skipped, and `DeletionPolicy:MaxBulkDeleteEmails` caps a single job.
- **Select All Matching** - Selection mode can select every email matching the current search across all pages, up to the selection limit, instead of one page at a time.

## ⚙️ Improvements
- **Lean Storage Groundwork (fork)** - New columns for lean storage (`ArchivedEmails.ContentStripped`, `EmailAttachments.PartPath`/`Sha256`), a MIME part locator and an original-message reader, and the option `RawMessages:FileSystem:HashNamed` to name original files by their SHA-256. All off by default; behaviour is unchanged until lean mode is enabled.
- **No Duplicate Archive Button on the Dashboard** - The header button led to the same email list as the archive search in the quick actions, so the dashboard title row no longer carries it.
- **Missing Originals Are Flagged on the Details Page** - With `RawMessages:Enabled`, the details page shows a notice above the headers for a message without a stored original. It asks the storage backend, so a filesystem file that vanished is flagged too.
- **Missing Original Messages Are Logged as Errors** - When an email is archived without its original, the log now carries an error with the email id and the reason: a message above `RawMessages:MaxMessageSizeMb`, a write failure in the configured backend, or a provider that delivered no usable capture. Previously the size case was silent and a write failure only surfaced as a generic "error saving archived email to database" line.
- **Pagination With Page Jump** - The email list now shows its navigation above and below the results, offers the first and last page plus a window around the current one, and has a field to jump directly to a page. A page number past the end lands on the last page instead of an empty list.
- **Resizable Table Columns** - The email list and the account overview let you drag a column edge to change its width, so a long sender address no longer squeezes the subject. The widths are not stored; a reload restores the natural layout.
- **Update Hint for Administrators** - When GitHub publishes a newer stable release than the installed version, administrators see a small toast in the lower right corner linking to that release. The toast is dismissed per version in the browser, drafts and prereleases are ignored, and the release list is refreshed every six hours instead of once per application lifetime.
- **Restore Uses the Stored Original** - Restoring an email to a mailbox now appends the stored original when one exists, the same cascade as the single-email export. Only emails archived without an original are rebuilt from the archived fields. A stored original that fails its checksum aborts the restore instead of falling back to the rebuild.
- **Original Message Storage Has Its Own Documentation Page** - The feature now has a dedicated page (`doc/RawMessages.md`) covering where the stored original is served, the postgres and filesystem backends, moving existing messages between them with `--migrate-raw-storage`, verification and backup. `Setup.md` keeps only the parameter table and links to it.
- **Multilingual Documentation** - The documentation is now published in every language the application supports. English stays the authoritative source; the other locales are translated automatically by an LLM through the new `translate-docs` workflow and carry a visible machine-translation notice.
- **Working Cross-References in Translated Pages** - A link to a heading inside a translated page pointed at an anchor that did not exist, because the anchor rewrite ignored the explicit `{#id}` target of a translated heading. The links now resolve to the same anchor as the English page.

## 🐛 Bug Fixes
- **Mailbox in the Access Log** - Deletion and retention entries now show which mailbox they belong to. The log view resolves the stored account id to the account name, so older entries are covered as well.
- **Account Table Keeps Actions Reachable on Narrow Screens** - Below roughly 1400 pixels the account table overflowed its card and pushed the page sideways, cutting off the sync and menu buttons. The table now scrolls inside the card, the actions column stays pinned to the right edge, and its dropdown opens outside the scroll container instead of being clipped.
- **Sessions End When the Account Changes** - Auth cookies were self-contained, so a password change, an administrator password reset, a deactivation or a role change left every other session valid until the cookie expired, up to seven days with "remember me". Cookies now carry a security stamp that is checked against the user on every request and rotated on those events. The browser that changes its own password is re-issued and stays signed in.
- **Deleting an Email Removes Its Stored Original** - With the `filesystem` backend the original message file survived every deletion. The metadata row went with the email through the foreign key cascade, but the file lives outside the database where no cascade can reach it. Retention rules, manual single and bulk deletion, and mail account deletion now remove the file as part of the same operation, after the email row is committed so a failed deletion cannot destroy an original. Files already orphaned by earlier deletions are reclaimed by a new periodic cleanup, so the disk space comes back.
- **Selection After Batch Delete** - The selection is cleared when a batch delete is submitted, so deleted emails no longer stay selected and inflate the counter.
- **Stable Sort Order in the Email List** - Rows that share a sort value (same subject, sender, or day) now fall back to the email id, so paging and "Select all matching" always agree on which emails come first.
- **Sign-In Messages in Every Language** - The OIDC messages for a pending approval, a deactivated account and a rejected sign-in were missing in eleven languages, so those deployments showed the English text. All locales now carry them.
- **Untranslated Labels and Messages** - Eight strings in the user and account screens, the restore and export views and the deletion status had no resource entry, so the interface displayed the internal key. They are translated in every language now.
- **Client Address in the Activity Log After a Proxy** - Authentication ran before the forwarded-headers middleware, so a sign-in recorded the reverse proxy's address and the proxy-facing scheme instead of the client's. Authentication now runs after it.
